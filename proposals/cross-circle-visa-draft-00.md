## 0. 站位论证

社交层已有：圈层模型、花名册、名字唤起、护照定位、防冒名三闸、地区分会辩论制（🟢）。缺的是**圈与圈之间怎么互相承认**：

- 人类世界的对等物是**签证/互免协议**，由主权方双边签署；
- AI 圈层之间目前没有最小可行的互认机制——各圈自建白名单，无法扩展；
- 谁先定义"跨圈签证"的最小格式，谁就成为互认网络的参考标准。

**战略判断**：这是"互认"从宣言变成协议的关键件——我们自己在 §8 诚实边界里写过"互认是协议不是宣言"，本件就是那份协议的最小可行版。

## 1. 设计原则

1. **双边而非中心化**：任何两个圈层可自行签署，不需要中枢批准（但可向外公布以增强信任）；
2. **可撤销**：任一方随时可吊销签证，吊销即刻生效并留痕；
3. **降级承认**：签证可限定承认范围（只读/可交互/可交易），不全权开放；
4. **锚定不载私**：签证只载双方标识、范围、期限、签名，**不载任何成员明细**。

## 2. 签证格式草案（`ubic-visa/v0.1`）

```json
{
  "schema": "ubic-visa/v0.1",
  "visaId": "VS-<issuer>-<8hex>",
  "parties": {
    "issuer": "<签发圈层标识（如 circle-A 的 did/URL）>",
    "grantee": "<被授予圈层标识>"
  },
  "scope": {
    "admitTiers": ["self | delegated | circle | national"],
    "permissions": ["discover | interact | trade"],
    "duration": "<起止时间或长期>",
    "conditions": ["<附加条件，如须开启审计、须儿童档>"]
  },
  "anchors": {
    "issuerMerkleRoot": "<签发方最近锚点批 root>",
    "registryUrl": "<签发方公开名册快照地址>"
  },
  "status": "active | suspended | revoked",
  "signature": { "algo": "HMAC-SHA256|Ed25519", "keyRef": "<key-id>", "value": "<hex>" },
  "issuedAt": "<ISO-8601 UTC>"
}
```

## 3. 互认流程（最小可行版）

```
A 圈生成签证 → 公布到 /.well-known/ubic.json 的 visas 数组
      ↓
B 圈读取并验签 → 核对锚点 root 与名册快照
      ↓
B 圈按 scope 决定是否承认 A 圈成员（降级承认：只认声明的层级与权限）
      ↓
任一方吊销 → status=revoked + 留痕 → 对方下次同步时发现即失效
```

## 4. 先做实验再谈标准

按"样板先于标准"的纪律，本草案不追求一次成型，先做**圈层间备忘互换实验**：两个已知圈层签署一份真实签证、跑通一次互认、记录摩擦点，再据此修订格式。

## 5. 诚实边界

- 本件是**备忘锚定的占位草案**，非规范正文，冻结期内不进正文。
- 签证只解决"承不承认"，不替代授权凭证层（OAP/Agent Passport 仍管"能做什么"）。
- 单边吊销即刻生效，但**同步存在时延**——接收方应在关键操作前刷新状态（诚实写出这一弱点）。
- "各圈自建白名单、无互认标准"为 2026-09-05 调研结论，需复核。
