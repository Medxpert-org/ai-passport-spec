## 1. 站位论证：监管三件套之间的空隙

2026 年全球医械 AI 监管三件套已经就位，但**每一件都差"身份与谱系"这口气**：

| 监管件 | 管什么 | 管不了什么（空隙） |
|---|---|---|
| **UDI**（中美欧全员） | 器械"壳"的身份：一器一码 | **壳里的 AI 换了 9 代脑子，UDI 纹丝不动** |
| **SBOM**（FDA FD&C 524B，2023 生效、2026 强化执法） | 组件清单：固件内嵌 AI 模型也须列入 | **清单是静态的**——"此刻哪台设备在跑哪个模型版本"不可查 |
| **PCCP**（FDA 2024-12 定稿） | 变更计划：预先声明允许哪些算法更新免新申报 | **计划≠执行记录**——实际改了什么、推给了谁，无身份化留痕 |

FDA 自己点名的第一安全关切是 **性能漂移（performance drift）**——而监测漂移的前提是**知道每台设备此刻跑的是哪个模型版本**。这件事全球没有制度化的答案。

**Contec CMS8000 事件（2025-01 FDA+CISA 联合通告）**是活案例：后门隐藏功能 + 联网数据外传——医械版的"影子智能体"。防线不是事后通告，是**凡连必签、凡造必登**。

**我们的站位：补第四件——医械 AI 子身份层。** UDI 管壳、SBOM 管清单、PCCP 管计划，**护照管"此刻是谁、从哪来、归谁治理"**。

## 2. 格式草案（ubic-deviceai/v0.1）

器械内嵌 AI 组件的护照文档（可独立，可挂主护照为子护照）：

```json
{
  "schema": "ubic-deviceai/v0.1",
  "subPassportId": "SDA-xxxx",
  "parentRef": {"udi": "(器械 UDI，DI+PI)", "devicePassportRef": "SP-xxx（可选）"},
  "aiComponent": {
    "name": "影像辅助判读模型",
    "version": "v9.2.1",
    "modelLineage": ["v1.0.0 ← 2023-06", "v5.1.0 ← 2024-11", "v9.2.1 ← 2026-08（PCCP-2024-017 授权变更）"],
    "pccpRef": "PCCP 编号（FDA 提交时声明的变更控制计划）",
    "sbomEntryRef": "SBOM 清单项引用（与 524B 对齐）"
  },
  "governance": {
    "issuerTier": "circle",
    "humanGate": "PCCP 范围外变更 → 新申报；范围内变更 → 变更登记自动留痕",
    "recallMatrixReady": true
  },
  "privacyTier": "patient"
}
```

**三个关键机制**：

1. **双标识挂接**：`udiRef ↔ subPassportId`——器械维修/转让时壳的身份不变，AI 组件的谱系独立延展
2. **变更登记 = PCCP 的执行面**：PCCP 声明"允许改什么"，护照链记录"实际改了什么、经谁批准、推送到哪些批次"——每次 OTA 更新 = 一次签发事件（人类闸门）
3. **召回精确制导**：召回不再按器械批次一刀切，而是**「器械 × 模型版本」矩阵**——定位"哪些 UDI 跑着受影响模型版本"，召回范围可缩一个数量级

## 3. 与三大监管框架的字段映射（对齐≠认证）

| 框架 | 我们的对接字段 | 状态 |
|---|---|---|
| **FDA**（524B SBOM / PCCP / QMSR-SPDF / DHF） | `sbomEntryRef`、`pccpRef`、谱系链入 DHF 可审计 | 🟡 映射草案 |
| **EU**（MDR / AI Act 2026 高风险 / CRA 2026 漏洞报告） | 模型谱系 = AI Act 日志要求的数据底座；CRA 漏洞通告按 `subPassportId` 定向 | 🟡 映射草案 |
| **中国**（GMP 2025 版 107 号公告 2026-11-01 施行 / NMPA AI 医械审查 / GB/Z 185） | `nationalIdRef` 预留（同主护照）；107 号公告的追溯要求以谱系链满足 | 🟡 映射草案 |

**诚实边界**：以上是结构与语义映射，不宣称"已通过任何监管认证"；正式对接需经各法域申报渠道。

## 4. 医械互联准入（Access Visa 延伸）

医院网络是"影子设备"重灾区（BYOD、第三方外设、未登记联网模块）。我们的设备签证模型（`device-access`）直接延伸：

- **凡连必签**：任何设备接入诊疗网络/UBIC-MedHub，先验 UDI + 子护照
- **患者最严档**：`privacyTier=patient` → 患者数据本地化（同儿童档机制），日志内容剥壳、原文零留存——合规基线（HIPAA/PIPL/GDPR）内建而非事后补
- **吊销即刻失效**：漏洞设备/失窃设备 → 吊销 → 网络拒绝
