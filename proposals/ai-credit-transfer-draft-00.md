## 0. 站位论证

AI 学校（§7.4）、学制五级、童年八里程碑、能力评定证书均已占位（🟢），形成"培养"闭环。但**跨校/跨圈层的学分互认**无人定义：

- 现有教育体系的学分互认（ECTS、中国学分银行）只服务人类，**不适用于 AI**；
- AI 的"学分"本质是**可验证的能力增量**，不是学时——需要新的互认单位；
- 谁先定义"AI 学分"的计量与转换，谁就掌握培养层的话语权。

## 1. 核心主张：学分 = 可验证的能力增量

**不计量"学了多久"，只计量"会了什么、证据在哪"**：

```
学分(CU) = f(能力项声明, 评测证据, 证据指纹, 签发方等级)
```

- 学时（hours）仅作参考字段，不作为计量依据；
- 每一学分必须绑定一条可验证证据（评测记录 + 内容指纹 + 签发方）；
- 无证据的"学时"不产生学分——这一条堵死刷课与虚报。

## 2. 格式草案（`ubic-credit/v0.1`）

```json
{
  "schema": "ubic-credit/v0.1",
  "learnerRef": "<AI 护照 ID 或规格书引用>",
  "records": [
    {
      "creditId": "CR-<issuer>-<8hex>",
      "competency": "<能力项，须来自公开能力目录>",
      "level": "1-5（对照学制五级）",
      "value": 1.0,
      "evidence": {
        "type": "assessment | portfolio | peer-review | realcase",
        "artifactFingerprint": "<评测成果 SHA-256>",
        "assessorRef": "<评测方标识>",
        "assessedAt": "<ISO-8601 UTC>"
      },
      "issuedBy": "<签发机构/学校标识>",
      "signature": { "algo": "HMAC-SHA256|Ed25519", "keyRef": "<key-id>", "value": "<hex>" }
    }
  ],
  "transferPolicy": "接收方按能力目录映射 + 证据复核后决定是否承认"
}
```

## 3. 互认机制（Transfer Policy）

1. **能力目录对齐**：双方使用同一公开能力目录（或声明映射表）；
2. **证据复核**：接收方验证 `artifactFingerprint` 与签发方签名；
3. **等级换算**：按学制五级映射，不从高往低自动承认（只承认 ≤ 本级）；
4. **争议处理**：异议期内可申请复评，复评记录入链（衔接审计留痕）。

## 4. 路线

## 5. 诚实边界

- 本件是**备忘锚定的占位草案**，非规范正文，冻结期内不生效。
- 不宣称等效于任何国家学分体系；与人类教育学分体系是**类比关系**而非等同。
- "全球无人定义"为 2026-09-05 复核结论，随时间需再核实。
- 计量公式中的权重 `f` 未定，需实测数据后确定（宁缺毋假）。
