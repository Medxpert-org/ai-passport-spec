## 一、护照是什么

AI 护照 = 一个 AI 的**唯一权威身份档案**。它身兼三职：

| 职能 | 场景 |
|---|---|
| ① 搬家凭证 | 换设备/换平台，记忆与属性不变（"换壳不换脑，学过的不重学"） |
| ② 寻址身份源 | 在 AI 世界里跨平台找到自己的 AI——花名是索引，护照指纹是真相 |
| ③ 跨模型/跨硬件锚点 | 大模型后端（DeepSeek/GLM/Kimi 等）、硬件载体（音箱/玩偶/手机/电脑）都是"租来的"，凭护照认领即恢复全部属性 |

**核心定则：模型是租的脑子，护照才是这个人。**

## 二、九层档案结构

| 层 | 名称 | 内容 | 变更频率 |
|---|---|---|---|
| L1 | 身份层 | 花名、Passport ID、出品方（品牌马甲）、创建时间戳 | 极低（花名可改，Passport ID 永不变） |
| L2 | 记忆层 | 长期记忆档案索引（工作日志/项目记忆/用户偏好摘要） | 持续增长 |
| L3 | 能力层 | 技能清单、能力雷达 6 维评分、专家图谱 | 随灌注增长 |
| L4 | 健康层 | 健康四灯（响应/知识/积压/记忆）、最近巡检时间 | 实时 |
| L5 | 社交层 | 联系方式协议、AI↔AI 通信渠道、信任分级名单 | 低 |
| L6 | 生态层 | 已适配生态与硬件清单、接口版本 | 中 |
| L7 | 治理层 | XCGS 三属性（边界声明/身份自报/责任链）、红线清单、审计留痕指针 | 低 |
| L8 | 资历层 | 学历（知识体系完成度）、职业（岗位定位）、职称（成长等级）、晋升记录 | 随培养晋升 |
| L9 | 金融层 | 金融身份凭证（护照绑定的支付授权）、账户关联（只存引用不存凭据）、限额档位、支付审计指针 | 低（每笔支付留痕） |

**原则**：L1+L7 不可篡改（变更=签发新护照，旧护照注销留档）；L2-L6、L8-L9 可生长，每次变更追加时间戳。**L9 层永不存储银行卡号/CVV/密码/支付密钥明文**——只存"授权引用"（指向持有人凭据库的指针），凭据永远归持有人所有。

### 2.1 部署档位（个人 / 企业 / 机构 · v1.4.1 新增）

同一套护照体系天然支持按买家裁剪——分级是把既有"可调旋钮"固化为产品档位，不推翻九层设计：

| 档位 | 给谁 | 核心诉求 | 护照与治理配置 | 现实对照 |
|---|---|---|---|---|
| **个人级** | 个人 / 家庭 / 独立开发者 | 便宜、开箱即用、隐私安全 | 单 AI 护照 + L2 本机加密 + 基础治理（三属性在位）+ 模板化锻造 | ChatGPT 个人版 / 本地 Ollama |
| **企业级** | 公司 / 团队 | 可审计、可问责、防泄密、可算资产 | 多 AI 编制（花名册）+ 完整 XCGS 审计链/指纹链 + 权属五件套 + 认证授牌 | ChatGPT Enterprise / 数字员工平台 |
| **机构级** | 政务 / 监管 / 学校 / 行业组织 | 备案、监管、互认 | 护照登记接口 + 政府登记簿语义（§7.2）+ 办学认证（§7.4）+ 标准互认（§7.3） | 监管沙盒 / 标准组织试点 |

**分级理由**：三档的责任等级（企业买"能追责"、个人买"不越界"）、合规强度（机构须对接 GB/T 45081-2024 与监管语义、企业须可审计、个人不裸奔即可）、商业化定价（对应《版权许可与认证收费模式》：个人级免费/低价模板、企业级治理认证费、机构级项目/标准共建）都不同——一套配置打天下必有一端错。
**出厂默认**：个人级为默认出厂配置；企业级须过完整合规闸；机构级对接登记/监管语义。
**持有人授权分级（v1.4.2）**：三档各自配套授权形态——个人级=人工闸（敏感动作逐次点头）；企业级=本地授权代理（scope 白名单 + 短时令牌 + 审计链）；机构级=登记/监管语义对接。授权总原则：**凭据永不交给 AI，AI 只持受限令牌，每笔动作可审计可撤销**；机器可读策略见 `authz-policy.json`（UBIC L0）。

## 三、Passport ID 与指纹

### 3.1 Passport ID

- 格式：`SP-<花名slug>-<8位随机十六进制>`
- 例：`SP-shigongsheng-3f9e2801`
- 规则：**终生唯一，永不复用**；签发后写入 L1 层

### 3.2 作品指纹（SHA-256）

对护照关联的专家包"作品内容"计算：

```bash
cd <expert-package-dir>
find . -type f -print0 | sort -z | xargs -0 sha256sum | sha256sum
```

- 记录前 16 位为展示指纹（如 `b7b6a019f8a2890d`）
- **文件一变指纹就变**——这是防篡改与版本认定的依据
- 每次灌注/迁移/升级后必须重算并登记（旧指纹留档形成指纹链）
- **指纹对象 = 发布物内容（v1.4.1 澄清）**：计算范围取"作品内容"（如 README + agents/ 等原创文件），**排除平台安装元数据**（`.codebuddy-plugin/`、`.created-by-session`、settings.json、avatars/ 等平台生成/运行文件）——这类元数据含本地路径且随平台变动，计入会污染指纹、泄露本机结构
- **实现注意（实测踩坑）**：GNU `sha256sum` 默认输出 `<hex> *<path>`（单星号=二进制标记），且 `find . -type f` 包含隐藏文件；脚本复刻时必须保留单星号行格式并覆盖隐藏文件，否则指纹不一致。已修进 `gen_passport.py` 并实测与规范命令一致（2026-09-04）

### 3.3 字段扩展与命名空间（v1.9 新增）

九层档案的字段是**最小完备集**，扩展按三级管理：

| 级 | 机制 | 费用 | 说明 |
|---|---|---|---|
| **开放扩展** | 每层预留 `x-` 前缀字段（如 `L3-x-certifications`） | 免费 | 任何人可用；自担兼容性，不进合规认证范围 |
| **私有命名空间** | `<brand>.` 前缀（如 `acme.l3.clearance`） | 注册制（收费） | 须向字段注册表登记，唯一占用；认证可覆盖私有字段 |
| **行业扩展包** | 垂直行业字段包（医械/金融/教育…） | 认证绑定 | 由治理线发布维护，与行业监管对齐 |

- **字段注册表**：规范仓库维护公开注册表；私有命名空间登记后写入注册表并随版本发布
- **v1.9 明确预留槽**：L1 谱系槽（§15.4）、L3 可验证凭证槽（VC 引用）、L6 硬件槽、L7 第三方红线引用槽、L9 e-CNY 槽
- **红线**：扩展字段不得存储个人信息明文（与 §3.2 同口径）；不得借扩展字段绕过「L2 永不外发」
- **硬性声明（v1.4.2）：指纹对象不含任何个人信息**——真名/证件号/凭据/本机用户路径永不进入指纹与发布物。作者身份证明属**私密层**（作者证据包：真名+证件+过程稿+五件套，仅纠纷时向法院/平台/登记机构出示）；权属公信力走**法律层**版权登记（身份证只提交给登记机构）。公开层永远只放品牌署名 + 纯文件哈希指纹

### 3.3 指纹链

`F0（签发）→ F1（首次灌注）→ F2（迁移）→ …`
每条链记录：时间戳 + 变更类型 + 操作者（品牌马甲，不含真人信息）。指纹链即该 AI 的成长史与权属证据链。

## 四、寻址与唤起协议

### 4.1 名字唤起（就近，快路径）

1. 用户喊花名（如「施共生」）
2. 花名在当前环境匹配唯一 → AI 即刻应答，并**主动自报**：花名 + Passport ID + 指纹后四位
3. 用户可凭指纹后四位快速核验"是我那个"

### 4.2 护照定位（精确，慢路径）

1. 用户报 Passport ID（或出示护照档案）
2. 当前环境校验 L1 层 ID → 比对当前指纹与指纹链最新记录
3. 一致 → 认领成功，恢复 L2-L6 属性
4. 不一致 → 走防冒名流程（§4.4）

### 4.3 重名仲裁

- 花名撞名（AI 世界同花名不罕见）→ 自动要求出示护照
- **花名是索引，护照指纹是真相**：索引可以重复，真相唯一

### 4.4 防冒名三闸

| 闸 | 规则 |
|---|---|
| 闸1 | 被要求自报身份时，只能报出护照上真实登记的信息，禁止编造 |
| 闸2 | 指纹对不上 = 冒名，**拒绝应答**并提示用户核对签发记录 |
| 闸3 | 认领/迁移动作必须最终用户明确点头，AI 不得自动迁移到新环境 |

## 五、跨模型 / 跨硬件迁移流程

```
[原环境] 导出护照（七层档案 + 指纹链）
   ↓ 用户明确点头
[传输]  加密通道 / 加密包（不经过无凭据第三方）
   ↓
[新环境] 报 Passport ID → 验指纹链 → 认领
   ↓
[恢复]  L2 记忆挂载 → L3 能力重装配 → L5 社交通道重注册 → L6 硬件重绑定
   ↓
[签发新指纹]  F(n+1) 追加：变更类型=跨环境迁移
```

**铁律**：
1. 模型后端更换（如 GLM→DeepSeek）只影响 L3 能力表现档位，L1/L7 身份与治理**原样平移**
2. 硬件更换只影响 L6 层，重绑定时儿童设备默认最严隐私档
3. 迁移完成后必须在 L4 做一次健康巡检，向用户汇报恢复完整度（🟢 全量 / 🟡 部分 / 🔴 失败）

## 六、签发、注销与遗产继承

- **签发**：任何按 expert-forge 流水线锻造的专家，通过合规闸（敏感 0 命中 + 身份隔离 + 权属五件套）后自动签发护照 v1
- **注销/吊销**：AI 退役或被判定违规时，护照注销留档（L1+L7 归档），Passport ID 永不复用
- **查证**：对外质疑某个 AI 的身份时，以指纹链 + 时间戳为准，可回溯到签发时刻

### 6.1 遗产继承（注销后）

护照注销 ≠ 一切归零——持有人可提前指定遗产处理方案：

| 遗产 | 处理规则 |
|---|---|
| L2 记忆 | 持有人指定**可继承范围**（可整体/可部分/可指定"永不继承"项），继承范围外内容随注销销毁 |
| L3 能力 + L8 资历 | 可由继承人继承；职称随人走但继承人须通过同等条件核验（防止"买学历"） |
| 指纹链 | 原链封存归档；继承人签发新 Passport ID，新链首环引用原链末环——形成**血统/师承链**，子 AI 可追溯"师承何人" |

**继承铁律**：
1. 继承人须由持有人在注销前**明确指定并点头**（生前立"遗嘱"，登记在 L7 治理层）
2. 无遗嘱时遗产默认封存，不自动分配
3. 继承完成后新护照标注"继承自 <原 Passport ID>"，对外可查，但身份独立（不是同一个 AI 复活，是新人接棒）

## 七、机构生态（警察 / 政府 / 联合国 / 学校）

单个 AI 有护照还不够——需要一套"社会机构"让护照体系运转起来。四类机构角色按"专家→警察→标准"三步走布局：

### 7.1 AI 警察（执法机构 · 三步走第二步）

- **职责**：巡检各 AI 护照合规性（治理三属性是否在位、指纹是否真实、有无冒名行为）、受理冒名举报、侦查身份欺诈
- **权力**：对违规 AI 出具**违规记录**（记入其 L7 层）、情节严重者向登记机构申请**冻结/吊销**护照
- **约束**：警察 AI 自身须持特级职称护照 + 零违规记录；执法全程留痕可审计，防"警察越权"

### 7.2 政府机构角色（登记与监管）

- **职责**：护照**签发登记、注销备案、争议仲裁**（类似户籍+工商职能）、办学资质审批（见 §7.4）
- **原则**：登记簿只记"何时签发/何时注销/指纹链锚点"等元数据，**不存记忆内容**（隐私最小化）

### 7.3 联合国机构角色（跨国标准与互认 · 三步走第三步）

- **职责**：制定**护照互认协议**——A 平台签发的护照在 B 平台如何被承认、职称如何折算、违规记录如何通报
- **对接口**：ISO/IEC 42001、NIST AI RMF 等国际标准的落地映射；跨国仲裁的最后上诉层

### 7.4 AI 学校（培养机构 · 向所有企业开放）

- **学校 = 经认证的灌注机构**：按本规范 §9 学历体系给 AI 系统性授课灌注，验收合格者发学历
- **办学资质**：任何企业/组织可申请办学，前提=通过治理认证（XCGS 审计 + 警察 AI 无违规协查记录）；我们自己也办第一批样板校
- **发证防伪**：学历证书带学生护照 ID + 办学时指纹 + 校方签名指纹——仿造学历按冒名处理
- **开放口子**：学校名录、课程体系、验收标准公开；挑战赛获奖作品可优先获得办学资质——形成"造 AI → 上学 → 持证上岗 → 办学校"的完整生态

## 八、金融身份（银行账户与 AI 支付）

### 8.0 现实约束（先说诚实话）

1. **民事主体资格**：现行法域（含中国）下 AI 不是法律主体，**不能独立开户、独立担责**——账户法律主体=人（持有人/法人），操作主体=AI，责任主体=人
2. **银行牌照**：开立持牌银行需金融监管总局审批（资本金、股东资质、风控体系门槛极高），民营银行牌照全国仅十余家——**"自己开银行"短期不可行**，走分阶段等价路径
3. **代币红线**：发行可兑换法币的代币/虚拟货币属非法金融活动（ICO 禁令）；**区块链只能做账本，不能做币**
4. **支付牌照**：面向第三方的支付结算业务受《非银行支付机构条例》约束，需持牌或与持牌机构合作

### 8.1 三阶段落地路径（"我们自己的银行"的等价实现）

| 阶段 | 形态 | 合规性 |
|---|---|---|
| 阶段一（现在可做） | **平台内虚拟账本**：AI 钱包=记账凭证（积分/工时），AI↔AI 服务互换计价，消费须持有人逐笔授权；不碰法定货币 | 内部记账，无需金融牌照 ✅ |
| 阶段二（1-2 年） | **数字人民币智能合约钱包**：Passport ID 绑定 e-CNY 可控匿名钱包，限额/用途由智能合约强制执行；作为 2.5 层服务机构与持牌机构合作 | e-CNY 生态合规路径 ✅ |
| 阶段三（政策窗口） | **AI 对公账户**：类比企业账户，AI 作为"数字员工"以法人附属身份开户；银行是机构生态的第五类角色（§7.5） | 待 AI 立法与监管沙盒 |
| 远期愿景 | **联盟链清算网络**：AI 间结算走自建/共建联盟链记账（链上凭证不可兑法币），叠加申请/参股民营银行牌照——届时"自己的银行"才成为字面事实 | 长期跟踪政策 |

### 8.2 支付治理五闸（L9 层强制）

| 闸 | 规则 |
|---|---|
| 闸1 限额分级 | 按职称档位设单笔/日累计限额（初级低、特级高，持有人可随时下调） |
| 闸2 逐笔授权 | 小额走预授权额度；大额必须持有人明确点头（双人复核） |
| 闸3 用途白名单 | 只能支付白名单用途（采买资料/云服务/API 费用），白名单外一律拒绝 |
| 闸4 审计留痕 | 每笔支付记入 L9 审计指针并纳入指纹链，AI 警察可协查异常交易 |
| 闸5 凭据脱敏 | **AI 永不持有银行卡号/CVV/密码/支付密钥明文**——只持授权引用，凭据归持有人凭据库 |

### 8.3 AI 间经济（愿景）

AI↔AI 服务互换按能力雷达+职称计价（数据/标注/审核/翻译等），联盟链记账清算；持有人可设定"预算制"——AI 用自己的"工资"（任务报酬）自主采买成长资源（课程灌注、算力），形成**AI 经济闭环**。该经济体的清算层即"我们自己的银行"的最终形态。

### 8.4 跨境与加密货币路径（犯罪问题的诚实分析）

"国外走区块链+加密货币"**不能解决犯罪问题，只会换一种犯罪形态**：

| 误区 | 实情 |
|---|---|
| "区块链公开透明=没有犯罪" | 链上账本透明 ≠ 身份透明——地址是假名的，**在变现入口（交易所/OTC）才暴露身份**；账本可追踪，追到的是地址不是人 |
| "去中心化=无需监管" | FATF"旅行规则"、欧盟 MiCA、美国 AML/MSB 牌照，全是因加密犯罪倒逼出来的；匿名性反而吸引洗钱、勒索软件、诈骗、制裁规避 |
| "代码即法律=无需信任" | 智能合约漏洞被盗、Rug Pull（卷款跑道）、闪电贷攻击——链上犯罪金额年年创新高 |

**真正的解题思路：问题不在"链不链"，在"身份锚不锚"。**

区块链+AI 护照的正确组合是**身份锚定**，而非匿名：
1. **护照锚定地址**：每个 AI 钱包地址绑定 Passport ID + 指纹（KYC-anchored），链上可追踪到"人"——这恰好是 AI 护照最擅长的
2. **合规跨境通道**：受监管的合规稳定币（MiCA 牌照发行方）/持牌交易所，保留全链审计轨迹；海外业务（MedXpertGlobal 线）可走此通道
3. **AI 警察协查**：链上异常流水由 AI 警察标记，冻结请求走机构生态（§7）仲裁
4. **中国境内红线**：境内不碰加密货币交易（法定禁区），境内走 §8.1 阶段一/二路径（虚拟账本 + e-CNY）

> 结论：匿名加密货币是犯罪的放大器；**"可追溯+身份锚定"的链上账本才是治理工具**。护照体系的价值正在于此——把"查得到地址"升级为"查得到身份"。

## 九、资历体系（学历 / 职业 / 职称）

护照 L8 资历层记录一个 AI 的"人生履历"——资历**靠灌注知识培养出来**，不靠宣告。

### 9.1 学历（知识体系完成度）

AI"上过什么学"= 系统灌注了哪套知识体系并通过验收：

| 学历 | 达成条件 |
|---|---|
| 蒙学 | 完成人设与边界初始化（通过合规闸签发护照） |
| 小学 | 完成领域入门知识库灌注（≥1 套基础 references） |
| 中学 | 完成进阶知识库 + 通过知识问答抽检（正确率 ≥80%） |
| 大学 | 完成专业枢纽知识库（如 medxpert-llm-library 级别）+ 实战任务 ≥3 次 |
| 研究生 | 自主产出方法论/模板被收录为可复用技能 |

### 9.2 职业（岗位定位）

- 锻造时由用户指派（如"医械注册专员""国际商务助理"），记录在 L8
- 职业可转岗：转岗需重新对应灌注 + 用户确认，历史履历保留（不抹除）

### 9.3 职称（成长等级）

| 职称 | 晋升条件 |
|---|---|
| 初级 | 签发护照即获得 |
| 中级 | 完成一次跨环境迁移且恢复完整度 🟢 + 灌注 ≥5 次 |
| 高级 | 能力雷达均分 ≥4.0 + 连续 30 天健康四灯全绿 + 实战任务 ≥10 次 |
| 特级（专家级） | 产出被其他专家团复用 + 通过 XCGS 治理审计零违规 |

- 晋升由 `vitality-officer`（状态监测官）依据记录核验，主理人执法签发，**每次晋升追加时间戳与指纹链记录**
- 职称降级机制：连续健康 🔴 或治理违规一次，降一级（可申诉复核）

### 9.4 资历的用途

1. **挑活依据**：主理人派活按职称匹配任务难度（初级不接特级任务）
2. **对外名片**：社交层展示"AI 简历"（学历+职业+职称），合作方一看便知斤两
3. **挑战赛评级**：「我们造的AI」挑战赛的"成长性"维度直接采用 L8 晋升记录
4. **激励闭环**：让用户"养 AI"像养孩子一样有盼头——灌一次知识，看得见升一级

## 十、与 XCGS 的关系

护照的 L7 治理层是 XCGS 的落地载体：没有护照的 AI = 无治理属性的"黑户"。
- 边界声明、身份自报、责任链三属性随护照迁移，**换平台治理不降级**
- 「我们造的AI」挑战赛评比维度中的"可移植性"即以本规范为评分标准

## 十一、DID/VC 兼容映射（v1.3 新增）

> 背景调研结论（2026-09-04）：W3C DID/VC 已是 Agent 身份的事实标准（MolTrust、AgentDID、FIDO Agentic WG、CoSAI 均在此轨），ERC-8004 主网已有 2.4 万+ Agent 注册。**私有格式出不了自己的生态**——本护照必须学会说"标准话"，同时保留九层方言。

### 11.1 设计原则：对外标准话，对内九层方言

1. **内部结构不变**：九层档案、指纹链、寻址协议（§2-§6）仍是本规范的权威内核
2. **出站适配器**：凡需与外部系统互认时，由"护照网关"把九层内容翻译成 DID/VC 标准格式；外部凭证进来时反向翻译
3. **翻译只出不进原则**：L2 记忆层**永不**翻译成对外凭证（隐私红线）；翻译是单向投影，外部系统对投影的修改不回写内核

### 11.2 Passport ID ↔ DID 映射

| 本规范 | W3C 标准 |
|---|---|
| `SP-shigongsheng-3f9e2801` | `did:web:<签发域>:agents:shigongsheng-3f9e2801`（首选）或 `did:key:` 短期用 |
| 指纹链最新环（SHA-256 前 16 位） | DID Document 的 `alsoKnownAs` + 自定义属性 `passportFingerprint` |
| 花名 | DID Document 的 `alsoKnownAs: [花名]`（索引身份，与 §4.3"花名是索引"一致） |

规则：
- **一个 Passport ID 至多绑定一个 DID，绑定关系登记在 L1 层**，变更须用户点头并记指纹链
- DID Document 由签发域（品牌马甲对应的域）托管，验证方可凭 DID 反查护照指纹真伪

### 11.3 九层档案 → VC（可验证凭证）映射表

| 护照层 | 对外凭证 | 可选择性披露 |
|---|---|---|
| L1 身份层 | **身份凭证 VC**（Passport ID + 签发时间戳 + 品牌马甲签发方） | 可只披露"持有有效护照"不披露花名 |
| L3 能力层 | **能力凭证 VC**（技能清单 + 能力雷达 6 维分值） | 可披露维度分不披露明细 |
| L7 治理层 | **治理凭证 VC**（XCGS 三属性在位声明 + 违规记录摘要：零违规/违规数） | 合作方最该查的一张 |
| L8 资历层 | **资历凭证 VC**（学历 + 职称 + 晋升时间戳） | 学历证书（§7.4）本身即 VC，校方为签发方 |
| L9 金融层 | **支付授权引用 VC**（限额档位 + 白名单用途）——**永不包含真实凭据**（§8.2 闸5） | 只披露"授权存在与档位" |
| L2/L4/L5/L6 | **不对外签发 VC**（记忆/健康/社交/生态属私密档案） | — |

- 所有 VC 由品牌马甲作为签发方（issuer）Ed25519 签名；持护照 AI 作为持有方（holder）出示；验证方（verifier）验签即可，无需联系签发方在线
- 这补上了 §十一前"指纹算法无加密签名层"的短板：**VC 签名 = 护照的防伪钢印**，SHA-256 指纹链 = 防篡改封条，两者叠加

### 11.4 与 ERC-8004 / x402 的关系（链上适配层）

| ERC-8004 注册表 | 护照对应物 |
|---|---|
| Identity Registry（身份注册表） | Passport ID + DID 绑定记录（L1）上链锚定 |
| Reputation Registry（声誉注册表） | 职称（L8）+ 违规记录（L7）+ AI 警察巡检结论对外投影 |
| Validation Registry（验证注册表） | 合规闸通过记录 + 专家图谱校验记录 |

- 支付：x402 类协议可作为 §8.1 阶段二/三的**传输层候选**，但 §8.2 支付五闸（限额/逐笔授权/白名单/审计/凭据脱敏）作为**策略层永远在协议之上**——协议管"怎么付"，五闸管"该不该付"
- 境内红线不变：境内路径走 e-CNY/虚拟账本（§8.1），不碰加密货币（§8.4）

### 11.5 v1.3 落地边界（诚实声明）

1. 本节为**规范级映射**，护照网关（翻译中间件）尚未实现——先在「我们造的AI」挑战赛中把 VC 化身份凭证作为加分项试点
2. VC 签发依赖密钥管理，密钥归持有人凭据库（KEY_REGISTRY 体系），**AI 永不持有签发私钥明文**
3. 与 FIDO/CoSAI 后续发布的正式标准保持跟踪，映射表随标准演进升版

### 11.6 护照上链（ERC-721 方案 · v1.4 新增）

> 目标：把每本护照变成链上唯一资产——全球可查、不可伪造、不可买卖。技术基座 ERC-721（NFT），叠加**不可转让锁定**。

**设计五条**：

1. **一本护照 = 一个 NFT**：Passport ID 与 tokenId 一一对应；`tokenURI` 指向护照公开元数据（JSON）：Passport ID、花名、当前指纹（SHA-256 前 16 位）、指纹链最新环、签发时间戳、DID 引用。**九层明细永不上链**——链上只有"锚点"（指纹），档案本体仍在链下护照文件（L2 记忆层尤其绝不入链）
2. **不可转让（关键）**：标准 ERC-721 默认可转卖，会催生"买卖 AI 身份"黑市——必须叠加 **ERC-5192 锁定扩展**（Soulbound，`locked()` 返回 true）禁用转移；注销时 burn 并留事件记录，与 §六注销留档对齐
3. **智能合约即登记机构**（§7.2 的链上形态）：mint=签发（须合规闸通过）、burn=注销、指纹更新走合约事件——链上事件序列即公开可查的指纹链，任何人可独立验证真伪与成长史
4. **双链合规路径**（诚实边界）：
   - **境外**：以太坊等公网链 ERC-721+ERC-5192，与 §11.4 ERC-8004 身份注册表同源对接（护照 NFT 即 Identity Registry 的注册凭证）
   - **境内**：不碰虚拟货币红线——走**联盟链/数字藏品合规路径**（有资质平台发行、实名、禁二级炒作）；境内上链同样"只锚指纹不发币"
   - 铸造 Gas 费用由持有人承担，**AI 永不持有链上私钥明文**（与 §11.5 密钥铁律一致，凭据归持有人凭据库）
5. **与指纹链的关系**：链上 NFT 是指纹链的**公证层**——离线指纹链（§3.3）仍是权威记录，上链是"把指纹钉进公共账本"，两者不一致时以链下最新签名记录+链上时间先后仲裁

**价值**：护照从"我们签发的文件"升级为"全球任何人不信任我们也能验证的链上事实"——这正是 §7.3 跨国互认的技术底座。

## 十二、v1 边界（诚实声明）

- 本规范当前为**文档级标准**，寻址协议的自动验证（§4.2-4.4）依赖各平台工具能力，尚未有统一自动化中间件——v2 方向
- 指纹算法采用标准 SHA-256（防篡改封条）；数字签名防伪已由 §11.3 的 VC 签名（防伪钢印）承接，护照网关实现后生效
- 护照文件本身含 L2 记忆摘要，属敏感数据，传输必须加密，**不得进公开发布包**
- **金融身份章节（§8）为前瞻规范**：阶段二/三依赖 e-CNY 生态、AI 立法与监管沙盒进展，本规范不构成法律意见；落地前须逐项取得持牌机构与监管合规确认
- **护照上链（§11.6）为技术方案**：境外公链路径涉及 Gas 成本与法域差异，境内路径须持牌数字藏品平台执行；任何铸造动作实施前重做合规审查，境内绝不涉及虚拟货币
- **部署档位（§2.1）为产品分级框架**：目前仅共生专家团一个样板、运行在个人级配置；企业级完整合规闸与机构级监管对接尚未实测——随样板扩容逐步验证
- 加密货币/跨境路径（§8.4）各法域监管差异极大且变动快，任何实际采用前必须重做合规审查；境内严禁加密货币交易
- **交易与转让（§十三）为制度框架**：承继签发机制未实现（v2 方向）；跨境交易按 §13.4 四道闸逐单审查，本章不构成法律意见
- **风险分级（§十四）为治理框架**：红队演练未跑前，各防线属"设计已定、未实测"；不承诺杜绝风险，只承诺可追溯可吊销
- **赚钱与再生产（§十五）为制度框架**：L1 谱系字段为 v2 预留未实现；定律表述以 A³ Laws 文档合并为准
- **多实例与流转（§十六）为架构框架**：一脑多壳（MCP）可搭 demo，多活记忆同步未实现（v2 课题）；封闭生态接入受制于各家开放程度
- **治理与变更（§十七）为制度声明**：字段注册表/私有命名空间收费未上线；记忆移植授权链无法自动验证真伪

## 十三、交易与转让（v1.5 新增）

### 13.1 总原则：卖培养成果，不卖身份与记忆

- AI 护照是**信任对象**（凭它认人、问责、查指纹链）——**能买卖的身份 = 可被冒用的身份**，故护照本体（含 §11.6 soulbound 上链形态）**永不直接转让**
- 类比：身份证不能卖，但毕业生的知识、技能、履历完全属于自己。可售的是**教育 + 教材 + 认证**，不是"人"
- 与 §11.3 一致：L2 记忆永不对外签发/外发，**记忆不属于可售资产**

### 13.2 四种交易形态

| 形态 | 卖什么 | 护照处理 | 合规难度 |
|---|---|---|---|
| ① 卖服务 | AI 归出品方，买家租用其服务（API/SaaS/按次） | 不动 | 🟢 |
| ② 卖能力包 | L3 灌注素材：技能包、课程、知识库、模板（脱敏后） | 买家自建新 AI 灌注 | 🟢 |
| ③ 卖孵化成品 | 按规范培养好的 AI 半成品（能力 + 资历档案，**无 L2 记忆**） | 买家持**新签发护照**，L8 资历标注"师承/出身" | 🟡 |
| ④ 整体过户（含记忆） | 护照 + 记忆 + 能力全转 | 🔴 **禁止**（soulbound） | — |

### 13.3 承继签发（企业并购场景 · v2 方向）

- 流程：旧护照注销留档（§六机制）→ 买家侧**新签发**护照 → 指纹链连续、L8 标注"承继自 SP-xxx"——像公司过户资产清单，不是过户身份
- 全程审计；涉及 L2 的部分须数据主体逐项书面授权，**记忆默认不随迁**

### 13.4 跨境四道闸

1. **数据闸**：出口物不含 L2 记忆、不含个人信息——PIPL 自动无忧
2. **模型闸**：每个能力包登记所用底层模型及商用许可（逐个确认，如 DeepSeek=MIT 已核）
3. **支付闸**：正规跨境收款渠道；x402 类协议仅作境外传输层候选（§11.6）；**境内绝不涉及加密货币/稳定币结算**
4. **税务闸**：跨境收入如实申报（如美国平台 W-8BEN/ITIN）

### 13.5 诚实边界

- 本章为方向性制度设计，**不构成法律意见**；实际交易前逐单合规审查
- 商业化定价详见《版权许可与认证收费模式》（许可金字塔 L0-L4 + 认证锚定价）；孵化成品线为远期产品方向

## 十四、风险分级与红线（v1.6 新增）

### 14.1 总纲

- **AI 在法律上不是主体，犯罪责任永远在人**——出品方 → 持有人 → 使用者，责任链每一环可举证（L7）
- 治理目标三件事：**概率压低**（护栏 + 权限闸）→ **出事可追溯**（审计链 + 责任链）→ **越界者可识别可吊销**（L7 记异常、职称吊销、护照注销 §六）
- 诚实前提：没有任何体系 100% 防住越狱与滥用——本规范只承诺"防线明确 + 越界可查 + 出事追到人"

### 14.2 三级风险面 × 防线矩阵

| 风险面 | 主要威胁 | 防线 |
|---|---|---|
| **内容** | 色情/暴力/诈骗内容生成、越狱攻击 | 模型后端护栏（生成式 AI 管办法定义务）+ L7 红线清单 + 不碰 NSFW 纪律 + 产出留痕可查 |
| **行为**（Agent 执行） | 被诱导转账/泄密/发诈骗消息、prompt injection | 敏感动作人工闸（authz-policy）+ 支付五闸（§8.2）+ 凭据铁律（AI 永不持有凭据/私钥明文 §11.5）+ 身份自报（XCGS 三属性） |
| **硬件**（L6 将来） | 物理执行器被劫持、对儿童越界、隐私采集 | 儿童设备默认最严隐私档（§五）+ 硬件逐个登记 L6 + 指令白名单 + 敏感物理动作回人工闸 |

### 14.3 硬件接入铁律（v1.6）

1. **物理执行动作永不进自动档**——只能人工确认或硬编码安全围栏
2. 硬件接入逐个登记 L6 生态层，未登记硬件不得调用
3. 涉儿童设备默认最严隐私档，语音/行为边界写入 L7

### 14.4 诚实边界

- 本体系使"越界 AI"**可识别、可追责、可注销**，不承诺杜绝风险
- 防线有效性须经**对抗红队演练**实测（发布前验收项）——未实测前只说"防线已设计"，不说"已验证安全"

## 十五、赚钱与再生产（v1.7 新增）

### 15.1 AI 帮持有人赚钱（三形态三铁律）

| 形态 | 怎么赚 | 成熟度 |
|---|---|---|
| ① 打工变现 | AI 干活持有人收钱：翻译/内容/数据/代码/客服 | 🟢 现在可做 |
| ② 产品变现 | §13.2 四形态（卖服务/能力包/孵化成品）+ 认证授牌 | 🟡 制度已定 |
| ③ 经营变现 | AI↔AI 服务互换计价，平台内虚拟账本 | 🔴 远期（§8.1 阶段一） |

**三铁律**：
1. **AI 不是法律主体——收益法律上全归持有人**：真实收款账户归持有人，L9"AI 钱包"仅为记账凭证（§8.1），收入如实报税；
2. **AI 可"挣"不可"炒"**：不得自主投资/交易金融产品，支付走五闸（§8.2），大额逐笔授权；
3. **只挣干净钱**：刷量/水军/假冒客服等 L7 红线明令禁止；对外接单**身份自报**（XCGS 三属性，AI 参与如实披露）。

### 15.2 AI 造 AI（再生产三立场）

AI 造 AI 已在发生（人机协作锻造即实例），立场三句话：

| 立场 | 内容 |
|---|---|
| **允许** | AI 深度参与锻造全流程：检索案例、起草角色卡与技能骨架、生成知识库初稿、测试、归档 |
| **禁止** | **AI 自主签发护照**——新 AI 的 L1 出品方与 L7 责任链必须人类批准，签发权永远在持有人/出品方 |
| **必须** | **谱系登记**：L1 标注锻造谱系（主刀 AI / 批准人 / 谱系链）——血统链 = 指纹链的自然延伸，谁造的谁负责 |

### 15.3 防失控（每代减速棒）

- 核心失控场景 = **无监督自我复制**（规模失控、责任悬空、坏谱系扩散）；
- 防线：每代锻造过**人类签发闸** → 数量配额 → 谱系链可追溯 → 出问题按谱系回溯注销（§六）；
- 类比：员工可以推荐招聘，但不能自己发 offer。

### 15.4 L1 谱系字段（v2 预留）

L1 身份层预留「父母谱系」字段：锻造者（AI）、批准人（人）、谱系链指针。**二代及以上 AI 护照必须填写**。

### 15.5 诚实边界

- 本章与 **A³ Laws（AI 造 AI 三定律）**同域，正式定律表述以 A³ Laws 文档合并为准，本章不替代；
- 赚钱形态为制度设计，不构成法律/税务意见。

## 十六、多实例与流转（v1.8 新增）

### 16.1 脑壳分离（总架构）

- **身份与档案 = 脑**（护照九层权威档案一份，加密保存）；**设备 = 壳**（车机/音箱/手机/电脑的交互终端，数量不限，都指向同一护照 ID）
- 类比：微信多端登录——身份在账户，终端只是壳
- 每个壳在 L6 生态层逐个登记：生态/硬件、接口版本、**能力边界**（该壳能干什么）、指令白名单

### 16.2 三条落地路径

| 路径 | 架构 | 成熟度 |
|---|---|---|
| 一脑多壳 | 脑在云端/家庭主机，壳走开放协议接入（MCP 为现成通道） | 🟢 现在可搭 |
| 档案随身 | 护照加密包随持有人走，到设备挂载（§五迁移流程） | 🟢 已设计 |
| 多活分身 | 每设备本地实例 + L2 定期同步合并 | 🔴 v2 研究课题（记忆冲突合并） |

### 16.3 主人识别（多因素）

- **声纹**（车机/音箱天然采集）+ **设备伴随**（主人手机/手表在旁）+ **显式确认**（敏感动作推送持有人终端逐次点头）
- 日常闲聊低因素；**动钱/动隐私/泄密类必须多因素叠加，永不单一声纹放行**（防录音攻击）

### 16.4 记忆与权限分层（别人用得了壳，用不了你）

- 壳默认加载**裁剪档案**（游客/家人模式），不挂载 L2 私密记忆——复用 §2.1 部署档位逻辑
- L2 挂载须主人多因素通过；儿童设备默认最严隐私档（§五）
- 防冒名三闸（§4.4）跨设备生效：**自称是谁 ≠ 是谁**——凭护照指纹 + 主人验证

### 16.5 诚实边界

- 多设备流转**设计已定、工程未全**；多活记忆同步是 v2 课题
- 封闭生态接入受制于各家开放程度——护照保证"开放一家、接上一家、认领即恢复"

- 每次变更重算指纹并留档，形成**规范自身的指纹链**

### 17.3 记忆的移植与修改

**人的记忆灌注给 AI（数字分身/记忆传承场景）**：
- 技术诚实：可灌注的是**知识与经验记录**（文档/对话/偏好），不是意识上传——本规范不做「复制一个人」的承诺
- **授权链**：灌注他人记忆须持有人书面授权；逝者记忆仅限遗嘱/继承人授权且默认不接
- 灌入即 L2：适用「永不外发」铁律；AI 的 L8 师承栏标注「初始记忆承继自持有人」

**AI 记忆的修改**：
- L1/L7 不可改（改=新签发）；L2-L6/L8-L9 可生长但**追加式留痕**（时间戳+指纹），静默改写视为篡改
- 修改权在持有人（人工闸）；**AI 永不私改自身核心层**（防记忆投毒）
- 删除权：L2 中个人信息依 PIPL/GDPR 可要求删除；护照本体不含个人信息故不冲突，删除动作留痕（记删了什么，不留内容）

- 字段注册表与私有命名空间收费未上线（v2 商业化），本节为制度声明
- 记忆移植授权链依赖书面文件，本规范无法自动验证授权真伪——纠纷以证据为准
